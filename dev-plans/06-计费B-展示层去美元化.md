# 06 计费阶段 B：展示层去美元化

| 项 | 内容 |
|---|---|
| 需求编号 | REQ-06 |
| 优先级 | P0-P1 |
| 预估工作量 | 2-3 天 |
| 前置依赖 | 05（需先确认 token 权重口径，否则展示文案无法定稿） |

## 1. 目标

在阶段 A 让 `spend` 数值等于加权 token 数之后，把 UI 上所有金额语义与 `$` 符号替换为 token 语义。完成后用户可见层面**完全无美元痕迹**。

## 2. 改造点清单（已通过代码调研定位）

### 2.1 核心：集中式格式化函数（改动收益最大）

| 文件 | 说明 |
|---|---|
| `ui/litellm-dashboard/src/utils/dataUtils.ts` | `getSpendString()`（约 50 行）是美元显示的主要出口，当前实现为 `` `$${formatted}` `` 与 `` `< $${threshold}` `` |

改造方向：

```ts
// 改造前
return `$${formatted}`;
// 改造后（示例）
return `${formatted} tokens`;   // 或按需带单位缩写：`${abbrev} tokens`
```

- 保留 `formatNumberWithCommas` 的缩写能力（`1.2M` → `1.2M tokens`）
- 极小值分支（`< $0.000001`）改为对应的 token 语义文案
- 配套测试 `src/utils/dataUtils.test.ts` 必须同步更新（这是该函数的回归保护）

### 2.5 文案与术语

- 「Max Budget (USD)」→「Token 配额」
- 「Spend」→「Token 用量」
- 表格表头：`Spend` → `用量 (tokens)`、`Budget` → `配额 (tokens)`
- tooltip 说明口径：明确指出输出 token 是否加权（与 05 号文档配置一致）
- `USD` 字样的提示文案（如「以美元计」）全部删除

## 3. 实施顺序（建议）

1. **先改 `getSpendString` + `money_cell` + `spend_budget_cell`**：三个点覆盖大部分展示，改完先跑一次全量 component test 看影响面
2. 再改预算相关页面（budgets 目录），这里文案密度最高
3. 然后改密钥/用户/团队等实体页面
4. 最后做一次全局 grep 收尾，逐个确认剩余 `$`

搜索收尾命令（复核用）：

```bash
grep -rn '\$' ui/litellm-dashboard/src --include=*.tsx --include=*.ts | grep -v schema.d.ts
```

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 遗漏零散的 `$` 字面量 | 全局 grep 收尾 + 页面手工走查（重点：budgets、usage、keys、users） |
| 改动文件多，与上游冲突 | 与 02 号文档第 2/3 批合并在同一分支实施；只改字符串与格式化函数，不改结构 |
| 数值精度展示 | token 为整数累加，展示直接 `formatNumberWithCommas`，移除金额精度分支 |
