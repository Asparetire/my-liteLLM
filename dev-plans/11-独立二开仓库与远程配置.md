## 1. 目标

建立一个**完全自主的二开仓库**，日常开发只推送到自己的仓库，永不推送到 LiteLLM 官方仓库；同时保留「看一看官方更新」的能力。

## 2. 已完成的本地拓扑

工作目录：`D:\project\litellm-cn`（本目录即二开主战场）

### 2.1 远程配置

| 远程 | 地址 | 权限 |
|---|---|---|
| `upstream` | `https://github.com/BerriAI/litellm.git` | **只能 fetch**，push 已被关闭（指向 `DISABLED_NO_PUSH`） |
| `backup` | `D:\project\litellm-fork.git` | 可读可写，本机裸仓库，作为本地备份与临时中转 |
| `origin` | 待接入：你的 GitHub 私有仓库 | 可读可写（日常开发唯一推送目标） |

关键机制：`git remote set-url --push upstream DISABLED_NO_PUSH` 把 upstream 的推送地址设成无效值，**即使手滑执行 `git push upstream` 也会立即失败**，从物理上杜绝误推官方仓库。

## 3. 待执行：设置 git 身份（必须先做）

当前机器上 `user.name` / `user.email` 为空，**任何 commit 都会被 git 拒绝**。在你的仓库目录执行一次（全局设置）：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的GitHub邮箱"
```

注意：`user.email` 要与 GitHub 账号的邮箱一致（或使用 GitHub 提供的 noreply 邮箱），否则提交不会归属到你的账号。

## 4. 待执行：接入 GitHub 私有仓库

### 第 1 步：在 GitHub 网页新建私有仓库

- 名称建议 `litellm-cn`
- **不要**勾选 Initialize this repository with a README / .gitignore / license（否则推送时会有历史冲突）
- 可见性选 Private

### 第 2 步：配置远程并推送

```bash
cd D:/project/litellm-cn

git remote add origin https://github.com/<你的用户名>/litellm-cn.git
git push -u origin main develop

# 单独设置跟踪（等价于 push -u 的效果，且不受本机 git 引用写入问题影响）
git config branch.main.remote origin
git config branch.main.merge refs/heads/main
git config branch.develop.remote origin
git config branch.develop.merge refs/heads/develop
```

若还要把历史标签一并推上去（约 600 个 tag，可选）：

```bash
git push origin --tags
```

### 第 3 步：验证

```bash
git remote -v          # origin 指向你的仓库，upstream 的 push 是 DISABLED_NO_PUSH
git branch -vv         # main / develop 均跟踪 origin
git push origin main   # 应提示 Everything up-to-date
git push upstream main # 应当失败（这是预期行为，证明误推已被堵死）
```

## 5. 日常开发流程

```bash
git checkout develop
git pull origin develop
git checkout -b feat/i18n-keys      # 按 dev-plans 编号切功能分支
# ... 开发 ...
git push -u origin feat/i18n-keys
```

合并回 develop 后，删除功能分支。

## 6. 看官方更新（不推送，只参考）

```bash
git fetch upstream                       # 拉官方最新代码到本地
git log --oneline HEAD..upstream/main    # 看官方多了哪些提交
git diff HEAD upstream/main --stat       # 看官方改了哪些文件
```

若打算吸收官方更新（可选，非必需）：

```bash
git checkout main
git fetch upstream
git merge --ff-only upstream/main        # main 始终只做镜像
git push origin main
git checkout develop
git merge main                           # 冲突在这一步集中处理
```
