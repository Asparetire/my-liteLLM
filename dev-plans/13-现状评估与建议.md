## 二、建议（按优先级）

### 1. 先补齐 git 分支结构（最紧迫）

本仓库只有 main 一个 commit，没有 develop 分支，违反 CLAUDE.md 的分支铁律（main 只跟上游，自有改动全部走 develop + feat 分支）。开始写代码前先建 develop，后续所有工作走 `feat/*` 分支。

```bash
git checkout -b develop
git push origin develop
```

### 2. 处理两个仓库卫生问题（2026-09-17 调研发现，未处理）

1. `deploy/ollama-litellm/litellm_config.yaml` 被 `.gitignore:102` 忽略（上游规则，怕带密钥）。200K 上下文、模型别名这些部署配置没进版本库，只以散文件存在。建议 `git add -f` 纳入，或改成 `litellm_config.example.yaml` + 本地实文件。
2. `deploy/deploy/ollama-litellm/` 是被 git 跟踪的重复旧快照（16 个文件，含没有补丁的旧 docker-compose.yml、qwen3.5 还是 32768 的旧配置）。照错路径部署会整份用回旧配置。清理需 `git rm -r`。

### 3. 按 M0 收敛，先做 06 再铺开 02

06 改 `getSpendString()`（dataUtils.ts:50）和 `src/components/shared/table_cells/money_cell.tsx`、`spend_budget_cell.tsx` 两个集中点，两三天能完成，M0 的"无美元残留"目标可先兑现。02 的 next-intl 基建完成后再按批次推进，避免汉化铺开太早导致 UI 测试大面积红。

### 4. 需求03 有一个测试风险，需先验证

中间件改写 `error.message` 后，上游 proxy 单测可能断言英文错误原文（如 `tests/test_litellm/proxy/hooks/test_max_budget_limiter.py`、`tests/test_litellm/proxy/auth/test_auth_checks.py`）。第一次跑通环境后执行 `make test-unit-proxy-core` 时重点关注；必要时让中间件只在生产配置开启（挂载点加环境开关），不干扰测试路径。

### 5. 消除双仓库歧义

2026-09-17 记忆中主战场是 `D:\project\litellm-cn`，当前仓库 `D:\project\litellm-src` 是自它导出的副本。两处同时改动会分叉。建议明确只保留一处作为开发目录，另一处归档。
