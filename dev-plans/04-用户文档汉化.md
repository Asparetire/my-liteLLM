## 1. 需求范围 ✅

「文档中的可见文本」包含三类，处理策略不同：

| 类别 | 位置 | 策略 | 状态 |
|---|---|---|---|
| A. 面向使用者的文档 | 仓库 docs 站点内容（本仓库 `docs/` 或 `my-website/docs/` 目录结构，随上游同步） | 在 `docs/zh-CN/` 下维护译文，零冲突 | 目录与 README 索引已建（2026-09-17 补全），首批篇目 ⏳ 待创建 |
| B. 面向使用者的仓库说明 | 根目录 `README.md` 等 | 不改原文，新增 `README.zh-CN.md` | ⏳ 已规划，文件未创建 |
| C. 代码内注释与开发者文档 | `CLAUDE.md`、模块 `README.md` 等 | **不翻译**（面向开发者，保持与上游一致，翻译只会制造冲突） | ✅ 已明确范围 |

> 注：`dev-plans/GIT-开发管理规范.md` 与 `docs/zh-CN/` 下的 `QUICK-START.md`、`private-llm-deployment-plan.md` 是自有开发者内容，不属于本需求的译文篇目。

| 英文 | 中文 | 说明 |

| Virtual Key / API Key | 虚拟密钥 / API 密钥 | UI 与文档共用 |
| Budget | Token 配额 | 改造后改为「Token 配额」，见 07 号文档 |
| Spend | Token 用量 | 改造后统一为 token 用量 |
| Rate Limit / TPM / RPM | 限流 / 每分钟 Token 数 / 每分钟请求数 | TPM、RPM 保留英文缩写 |
| Team / Organization / User | 团队 / 组织 / 用户 | |
| Model Access Group | 模型访问组 | |
| Guardrail | 护栏 | |
| Router / Fallback | 路由 / 回退 | |
| Provider | 提供商 | |
| Token | Token | 不译 |

## 5. 文档创作规范 ✅

### 5.1 翻译流程

1. 在 dev-plans/04-用户文档汉化.md 中登记需求
2. 翻译完成后放入 docs/zh-CN/<页面名>-zh.md
3. 待合并回 main 分支时批量更新上游 docs/

### 5.2 文件命名规范

```bash
<主题>-zh.md    # 中文翻译
<topic>-en.md   # 保留英文原文（回退）
```

### 5.3 翻译注意事项

- **不改技术名词**：API 字段、命令参数、环境变量名保持英文
- **注意代码示例**：所有代码块保持英文，仅在注释中添加中文说明
- **对照原文**：每篇译文头部需标注上游文档链接或 commit 哈希
- **术语一致**：使用统一术语表中的译法
