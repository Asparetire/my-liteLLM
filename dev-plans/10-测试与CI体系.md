# 10 测试与 CI 体系

| 项 | 内容 |
|---|---|
| 需求编号 | REQ-10 |
| 优先级 | P1-P2（流水线搭建 3 天，之后持续运行） |
| 预估工作量 | 3 天搭建 + 持续 |
| 前置依赖 | 01（分支模型确定后才能定义流水线触发规则） |

## 1. 目标

二开改动（尤其是汉化与计费）必须有一套**能自动拦住回归的闸门**。上游自带完整的测试基建，本需求是把它接入自有 CI，而不是另造一套。

## 2. 现成的测试资产（直接复用）

| 层级 | 命令 / 位置 | 说明 |
|---|---|---|
| UI 单测 | `npm run test:unit`（`ui/litellm-dashboard`） | vitest unit project |
| UI 组件测试 | `npm run test:component` | 汉化与展示层改造的主力回归 |
| UI 集成测试 | `npm run test:integration` | 跨组件交互 |
| UI 类型检查 | `npm run test:types` | 类型契约 |
| 后端单测 | `make test-unit` / `make check` | 含 lint 与类型门禁 |
| 预算功能 e2e | `tests/e2e/quota_management/budgets/` | 已有预算执行/重置/预留等用例，token 配额需在此扩展 |
| 迁移守卫 | `tests/code_coverage_tests/check_migrations_no_data_rewrites.py` | 强约束：迁移不得重写行 |
| 端到端冒烟 | `tests/e2e/` | 按该目录 `CLAUDE.md` 的约定编写 |

## 3. CI 流水线设计

### 3.1 触发规则

| 事件 | 执行内容 |
|---|---|
| push 到 `feat/*` | 快速检查：lint + 相关目录单测 + 构建 |
| PR 合并到 `develop` | 完整：lint + 全量单测 + UI 三套测试 + 构建 |
| 定期（每周） | 全量回归 + 上游同步演练（合并 `main` 后跑一遍） |
| 发布前 | 全量 + e2e 冒烟（真实调用国内模型） |

### 3.2 流水线阶段

```
1. 环境准备（Node >= 24.14.1、Python 3.x、依赖缓存）
2. Lint / 类型
   - Python: make lint（或 scripts/pre_commit_lint.sh）
   - UI: npm run lint + npm run test:types
3. 单元测试
   - Python: make test-unit
   - UI: npm run test:unit && npm run test:component
4. 构建
   - UI: npm run build
   - 镜像: docker build
5. 迁移守卫
   - python tests/code_coverage_tests/check_migrations_no_data_rewrites.py
6. 二开专项校验（自定义，见第 4 节）
```

> 注意：仓库的 lint/类型门禁有机器级并发槽位限制（同时只能跑有限个），CI 上不要并发触发多套 `make check`，否则会排队等待。

## 4. 二开专项校验（自建，进 CI）

| 校验项 | 实现方式 | 目的 |
|---|---|---|
| 汉化覆盖率 | 对比 `messages/zh-CN.json` 与 `en.json` 的 key 差集，输出未翻译数量 | 量化汉化进度，防止翻译丢失 |
| 错误译文校验 | 03 号文档的 `litellm_cn` 校验脚本：`zh-CN.json` 的 key 必须存在于 `en.json` | 防止僵尸/错别字条目 |
| 美元残留检查 | grep 用户可见目录中的 `$` / `USD`（排除 `schema.d.ts` 与注释） | 保证去美元化彻底 |
| 红线检查 | 校验 API 字段名、DB 列名未被翻译（对比 `schema.prisma` 与 OpenAPI 快照） | 防止「翻译到协议层」的破坏性改动 |
| `[CN-FORK]` 标记统计 | 统计改动上游文件的数量与分布 | 量化冲突面，超过阈值时告警 |

## 5. 回归测试要求（按需求）

| 需求 | 必须有的回归 |
|---|---|
| 02 UI 汉化 | 被改动页面的 component test 同步更新并通过；语言切换冒烟 |
| 03 错误汉化 | 命中/未命中/非 JSON 响应/正常响应不被改写 |
| 05 计费 A | `spend == total_tokens` 的核对脚本（可作为冒烟检查） |
| 06 计费 B | `getSpendString` 全分支 + 预算展示组件 |
| 07 计费 C | token 配额超限 / null 回退 / 整数精度 / 并发预留 / 周期重置 |
| 08 提供商接入 | 每个已接入模型的连通性冒烟（真实调用，成本很低） |

## 6. 端到端冒烟规范

遵循上游偏好：**用 curl 打本地 proxy，不用 mock**。

```bash
# 起 proxy（参考上游建议的启动方式）
python litellm/proxy/proxy_cli.py --config litellm/proxy/dev_config.yaml --detailed_debug --reload

# 冒烟：正常调用
curl -s http://localhost:4000/v1/chat/completions -H "Authorization: Bearer $KEY" ...

# 冒烟：配额用尽返回 429
curl -s -o /dev/null -w '%{http_code}\n' http://localhost:4000/v1/chat/completions -H "Authorization: Bearer $EXHAUSTED_KEY" ...

# 冒烟：核对计量
curl -s "http://localhost:4000/key/info?key=$KEY" -H "Authorization: Bearer $MASTER_KEY"
```

UI 相关改动需附**前后截图**（汉化前后、去美元前后）。

## 7. 提交与合并规范

- 提交遵循 conventional commits（`feat:`、`fix:`、`chore:` 等），不加任何 AI 署名
- 一个需求一个分支，合回 `develop` 前必须 CI 全绿
- 每周固定一次 `develop` 合并 `main` 的同步演练，记录冲突文件清单（作为 01 号文档的输入）

## 8. 验收标准

- [ ] CI 流水线在 push / PR / 定期三种触发下工作正常
- [ ] 5 项二开专项校验全部接入并产出报告
- [ ] 一次真实上游合并后，整套测试能跑通并暴露真实冲突
- [ ] 冒烟脚本可在本地一键执行
- [ ] 测试失败时能明确定位到具体需求编号
