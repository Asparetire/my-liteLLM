## Ollama + LiteLLM 组合部署

用户决定用 Ollama 做私有推理后端，LiteLLM 做网关。核实到的代码事实（litellm v1.102.0）：

- **provider 前缀二选一，很关键**：
  - `ollama/<model>` → `litellm/llms/ollama/completion/transformation.py` → `POST /api/generate`（把 messages 拼成纯文本 prompt，多轮与 tools 不可靠）
  - `ollama_chat/<model>` → `litellm/llms/ollama/chat/transformation.py` → `POST /api/chat`（推荐）。仓库 `tests/local_testing/test_ollama.py` 里有注释明确要求用 `ollama_chat`。
  - 模型名可带 tag：`ollama_chat/qwen3:14b`、`ollama_chat/qwen2.5:0.5b`。
- 默认 api_base 为 `http://localhost:11434`，可用环境变量 `OLLAMA_API_BASE` 覆盖（`litellm/main.py`、`litellm_core_utils/get_llm_provider_logic.py`）。
- Ollama 特有参数 `num_ctx`、`num_predict`、`mirostat*` 等定义在 `OllamaChatConfig`，可通过 config 的 `litellm_params` 透传。
- 本地模型无价格表，建议在 litellm_params 显式写 `input_cost_per_token: 0` / `output_cost_per_token: 0`。

## Ollama 侧关键配置（默认值的坑）

- `OLLAMA_NUM_PARALLEL` 默认 **1**，即串行处理，必须调大（如 4），否则并发全排队。
- `OLLAMA_KEEP_ALIVE` 默认 5m，到期卸载模型，下一次请求冷启动几十秒，建议 24h 或 -1。
- `OLLAMA_HOST` 默认 127.0.0.1:11434，容器外访问需设 0.0.0.0:11434。
- 其他：`OLLAMA_MODELS`（模型目录）、`OLLAMA_MAX_LOADED_MODELS`（默认 0=auto）、`OLLAMA_MAX_QUEUE`（512）、`OLLAMA_FLASH_ATTENTION`、`OLLAMA_SCHED_SPREAD`（多卡分摊）、`OLLAMA_NO_CLOUD`。
- systemd 部署用 `systemctl edit ollama` 加 `[Service] Environment="..."`。

## 模型选型口径（给用户的一致说法）

- 权重显存估算：`参数量(B) × 0.6 GB`（Q4_K_M）；硬约束是权重 ≤ 单卡显存 × 0.75，余量给 KV cache 与并发 slot。
- 档位：≤8GB→qwen3:4b；12-16GB→qwen3:8b/14b；24GB→qwen3:32b 或 MoE 30b-a3b；48GB+→32b 高位量化；80GB→FP8/多模型常驻。
- 中文场景首选 Qwen3 系列（Apache 2.0）。嵌入模型用 `qwen3-embedding:0.6b/4b`。

## 关键排障：llama-server binary not found

- 现象：`ollama --version` 正常（0.34.1），但 `ollama serve` 报 `error starting llama-server: llama-server binary not found`，候选路径含 `/usr/local/lib/ollama/llama-server`。
- 根因：**Ollama 由两个二进制组成** —— 主程序 `/usr/local/bin/ollama` + 推理引擎 `/usr/local/lib/ollama/llama-server`。解压 tar.zst 时只装上了前者（解压中断或不完整），所以 `--version` 能跑、`serve` 失败。
- 修复：`sudo tar -I zstd -xvf /tmp/ollama.tar.zst -C /usr/local`，确认 `/usr/local/lib/ollama/llama-server` 存在并 `chmod +x`。
- 排查此类问题的通用手段：`sudo -u ollama timeout 15 /usr/local/bin/ollama serve` 前台直跑，能以 systemd 相同身份暴露真实错误（比 journalctl 有效，尤其 systemd 尚未成功启动过、日志为空时）。
- 已在 `deploy.sh` 第 1 步加入该检查：缺失时自动 `find /usr/local /tmp /opt` 并复制，找不到则打印重新解压/下载命令后退出。
