# 每轮结构化工作记录与下一步规划（强制规范）

本项目（litellm-src 二开）每一轮对话收尾时，无论本次任务大小（写代码、提问、调试、改错、优化都算），都必须在回复末尾输出下文第四节的两段固定模板。用户不再重复提醒。

## 一、工作记录要求（强制）

1. **本次完成工作内容**：具体、落地、可追溯。写清代码修改点、新增功能、修复问题、配置变更、逻辑优化；明确改动文件、改动范围、实现效果
2. **当前工程完成进度**：全局视角。已完成模块清单、未完成模块清单、整体进度百分比估算、项目状态（正常/阻塞/待补充/待调试）
3. **当前存在的问题、风险、待验证点**：潜在 bug、逻辑缺陷、未完善点、需要后续验证测试补充的内容

## 二、下一步规划要求（强制、可直接执行）

结构固定为三级优先级，每条必须具体到：做什么、改哪些文件、实现什么效果、解决什么问题。

- P0（紧急必做）：必须马上补全/修复/实现的内容
- P1（下轮迭代）：下一轮开发要做的功能
- P2（长期优化）：优化、重构、扩展性、稳定性、文档补充

## 三、永久规则

- 进度是持续累积的，不能每次清空、不能遗忘历史进度
- 用户开新任务时，自动把新任务融入整体项目进度中
- 记录简洁、结构化、工程化，不废话、不浮夸
- 遵守仓库 CLAUDE.md 的人类可读文本规范（无 emoji、少用破折号、不用 "It's not X, it's Y"）

## 四、固定输出模板（每轮结尾严格使用）

```
【本轮工作记录】
1. 本次完成：……
2. 当前工程进度：……
3. 现存问题与待验证点：……

【下一步工作规划】
P0（紧急必做）：……
P1（下轮迭代）：……
P2（长期优化）：……
```

## 五、进度数据来源（防三套记录脱节）

聊天模板是展示层，真实进度以文件为准，不凭印象编造：

- **会话级快照**：Claude 记忆目录的 `project-status.md`（每会话开始自动加载，收尾时更新）
- **里程碑记录**：仓库 `dev-plans/13-现状评估与建议.md`（批次完成、上线、合分支时追加小节）
- **批次计划基线**：`C:\Users\Administrator\.claude\plans\stateful-yawning-rossum.md`（REQ-02 批次4-8 与挂账队列）

P0/P1/P2 与批次计划对齐，不另起炉灶；模板中的进度百分比和模块清单必须与上述文件一致。若本轮是纯问答（无代码改动），"本次完成"如实写明解答内容即可，同样更新规划。
